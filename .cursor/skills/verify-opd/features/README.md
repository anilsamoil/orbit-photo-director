# SNAP verification map

This directory is the source for driving SNAP the way an astronaut does. Read this index, then use one feature file as the recipe.

## Baseline preconditions

- Run `node .cursor/skills/verify-opd/scripts/opd-verify.mjs up` from the repo root.
- Run `node .cursor/skills/verify-opd/scripts/opd-verify.mjs doctor` and require the `ok` line, the proxy pid, and a launch `valid_until` in the future. A green `doctor` after `drive` does not mean Verify Reef and Verify Delta are still in the 90-minute queue. Reef leaves 20 minutes after `up`, and Delta leaves at 50 minutes. Run `down`, then `up`, and rerun.
- Open only the URL `doctor` prints. The default is `http://127.0.0.1:41731`.
- Keep a second run on its own `OPD_VERIFY_HOME` and `OPD_VERIFY_PORT`.
- The fixture signs in as Anil. Cards are `Verify Reef`, `Verify Delta`, `Verify Mesa`, and `Verify Keepsake`. `Verify Ascent` is the Shot highlight, `Verify Likely` is a pad with no corridor, and `Verify Horizon` is Watch. Upcoming and the map list Ascent and Likely. They do not list Horizon.
- That sign-in is the Anil fixture. The drive does not send `Cf-Access-Jwt-Assertion`, and the proxy is not the Worker. A green drive does not prove the Access gate. The gate check is `cd worker && bunx vitest run --config ../.cursor/skills/verify-opd/scripts/vitest.config.mjs`. It sets `ACCESS_ALLOWED_EMAILS` to `allowed-one@example.test`. `off-list@example.test` gets 403 `{error: email_not_allowlisted}` on `/`, `/sw.js`, and `/api/health`. An empty, unset, BOM, or U+00A0 list returns that 403 for every human. A service token gets 200 on exact `/api/health` and 401 elsewhere. No JWT gets 401. `/api/profiles/*` needs `x-calib-token`. `bash worker/deploy.test.sh` refuses a blank or newline `ACCESS_ALLOWED_EMAILS` with exit 2 under both `LC_ALL=C` and `LC_ALL=en_US.UTF-8`. `bash scripts/upload_frontend.test.sh` is the upload checklist. Neither script deploys. The Worker go-live for this allowlist is still pending. It is not deployed. When the Mac's wrangler has no R2 auth, `scripts/upload_frontend.sh` cannot run. The sanctioned fallback, used for #291, is additive `rclone copy` of the same files in the same order, `sw.js` last, never `rclone sync`. This skill does not run it. Both public hosts are `https://map.astroanil.dev` and `https://map.expedition75.com`. Do not fetch them. The zone redirect on the second host is disabled, not deleted. Shot-list calendar links use the page host.

## Driving conventions

- Start each feature from the healthy instance unless its preconditions say otherwise.
- Prefer the ids and accessible names in the feature file.
- `drive all` walks banner, topbar, queue, upcoming, map, iss, help, profile, log, phone, and tracked in that order on desktop Chrome, then runs those same steps on WebKit iPhone 13, iPhone 17 Pro, and iPad Pro 11. A single feature drive does the same four surfaces. WebKit missing fails the drive. `OPD_VERIFY_SURFACE` limits one process to `desktop`, `iphone-13`, `iphone-17-pro`, `ipad-pro-11`, or the non-blocking `ipad-3`. There is no `874x402` value. iPhone 17 Pro starts at 402 by 874. iPad Pro 11 starts at 834 by 1194. A separate WebKit process at 874 by 402 is `OPD_VERIFY_SURFACE=iphone-17-pro OPD_VERIFY_VIEWPORT=874x402`, which creates the Playwright context at that size. Its shots are `evidence/iphone-17-pro-874x402/`. A later `page.setViewportSize` is not that viewport. Each drive prints the opened size and `created-at-size`, `chrome-metrics`, or `device-context`. Blocking targets (Anil 2026-10-15) are desktop Chromium, WebKit iPhone 17 Pro at 402 by 874 plus a context created at 874 by 402, and WebKit iPad M4 at 834 by 1210 and 1210 by 834, each created at that size. M4 is `OPD_VERIFY_SURFACE=ipad-pro-11 OPD_VERIFY_VIEWPORT=834x1210` or `1210x834`. Shots land in `evidence/ipad-pro-11-834x1210/` and `evidence/ipad-pro-11-1210x834/`. The stock iPad Pro 11 descriptor stays 834 by 1194. iPhone 13, that stock size, the 3rd-generation iPad, and other sizes are non-blocking notes. The 3rd-generation iPad is the non-blocking surface `ipad-3`: WebKit, a Safari tab, DPR 2, portrait `768x1024` and landscape `1024x768`, each context created at that size. Anil uses that iPad in Safari. `drive all` leaves it out. `OPD_VERIFY_SURFACE=ipad-3 OPD_VERIFY_VIEWPORT=768x1024` and `OPD_VERIFY_VIEWPORT=1024x768` are the two drives. Shots land in `evidence/ipad-3-768x1024/` and `evidence/ipad-3-1024x768/`. The blocking set stays desktop Chromium, iPhone 17 Pro at 402 by 874 and 874 by 402, and iPad M4 at 834 by 1210 and 1210 by 834. The default pass still runs desktop, iPhone 13, iPhone 17 Pro, and iPad Pro 11. `OPD_VERIFY_VIEWPORT` is legal for `desktop` at `1440x900` or `1280x800`, for `iphone-17-pro` at any `WIDTHxHEIGHT`, for `iphone-13` at `844x390`, for `ipad-pro-11` at `834x1210` or `1210x834`, and for `ipad-3` at `768x1024` or `1024x768`. Any other surface with that variable set throws. WebKit has no `Emulation.setSafeAreaInsetsOverride`, so `env(safe-area-inset-*)` reads 0. Nonzero insets come from Chromium CDP. A combined process that hits `page.goto: WebKit encountered an internal error` inside `proveHeldSignIn` is not the surface verdict. Run one surface per process. A flake of `iss launch earth restored 390x664` gets one solo fresh-process retry of `iphone-13`. Known harness flakes on iPhone 13, iPhone 17 Pro, and iPad Pro 11 also include a WPENetworkProcess segfault or abort during the towns reload or the held sign-in, and `held SIGN IN AGAIN banner timed out` with last value null. One fresh-process retry of that surface is the check. Use `down`, then `up`, when the proxy or the page is wedged. The same one-retry rule covers a WebKit internal error, a stale TLE banner timeout, `map restored`, `iss launch lost`, `queue restored` or queue cards, `map chrome stored hidden`, `iss towns blocked`, and `banner after reload timed out` with last value null.
- `sw` builds a preview and is not part of `drive all`.
- `down` deletes the Chrome profile and keeps `evidence/`.

## Proof and skip reporting

- Save the PNG for the action, not only the last screen.
- Record the feature id in the script stdout.
- If a path cannot be reached, record the command and the unmet precondition. Do not mark it verified by a different path.
