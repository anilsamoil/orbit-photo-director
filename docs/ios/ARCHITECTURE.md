# SNAP for iPhone and iPad: architecture

The target shape for release 1 and the contracts between its parts. The decisions and their reasons are in [the design doc](../designs/ios-app.md). The order of work is in [WORK_PLAN.md](WORK_PLAN.md). Where this file says "gate G1 decides", the answer is not known yet and a work package exists to find it.

## The shape

```

│ generator daemon   │ publish│ guarded publisher and R2 │       │ SNAP.app                          │
│ every 60 min       ├───────►│ Worker                   │       │ ┌───────────────────────────────┐ │
└────────────────────┘        │  /      website, Access  │       │ │ web view: the built frontend  │ │

                              │         checked by Worker│ HTTPS │                │ bridge           │
                              └──────────────────────────┘       │ ┌──────────────┴────────────────┐ │
                                                                 │ │ native: Sync, PlanStore,      │ │
                                                                 │ │ Outbox, TileGateway, Alerts,  │ │
                                                                 │ │ Credential, Diagnostics       │ │

                                                                 └───────────────────────────────────┘
```

The web view draws every screen. Native code serves the bundled app and brokers its account and tile requests.

## Nouns

Use these words and no synonyms.

| Word | Meaning |
| --- | --- |
| host | What SNAP runs inside: `browser` or `ios`. |
| host seam | `frontend/src/host/`. The only web code that knows the host. |
| bridge | How the `ios` side of the seam calls native code. Hidden behind the seam. |
| plan | One published version. The device receives a grant-filtered `manifest.json` and the artifacts it names. |
| installed plan | A plan the device has downloaded, verified and stored for an account. |
| extended queue | Passes the device computes from now to seven days ahead, replaced by published scored passes where they exist. Geometry and lighting only. |
| alert plan | The list of alerts the web side hands to native code. |
| outbox | The durable list of writes not yet acknowledged by the server. |
| baseline pack | The map tiles shipped inside the app. |
| tile store | Tiles kept on disk after they were fetched. |
| enrollment | The one-time sign-in that binds a device to a profile. |
| device token | The credential a device receives at enrollment. |

## The host seam

One object, chosen once at startup. The browser side preserves existing requests within the W-20 authorization, session, and personal-data policies, including [target request privacy](#target-request-privacy). The iOS side calls the bridge.

```ts
export type HostStartup =
  | { kind: 'public'; snapshotVersion: string }
  | { kind: 'account'; snapshotVersion: string };

export interface Host {
  readonly kind: 'browser' | 'ios';
  readonly capabilities: ReadonlySet<string>;      // 'plans.v1', 'outbox.v1', 'tiles.v1', 'alerts.v1', 'identity.v1', 'diagnostics.v1', 'startup.v1', 'file-export.v1'

  /** Every request to SNAP's own origin. Never called for another origin. */
  request(path: string, init?: HostRequestInit): Promise<Response>;

  online(): boolean;
  probe(): Promise<boolean>;
  on(event: 'plan-installed' | 'connectivity' | 'foreground' | 'memory-warning', cb: () => void): () => void;

  snapshot: { read(): Snapshot | null; write(s: Snapshot): boolean; clear(): void };
  outbox:   { enqueue(p: CalibPayload): Promise<void>; count(): number; drain(): Promise<number>; list(): CalibPayload[] };
  tileUrl(layer: TileLayerId, upstream: string): string;

  startup?(): Promise<HostStartup>;
  identity?:    { current(): HostIdentity; enroll(): Promise<HostIdentity>; forget(): Promise<void> };
  alerts?:      { setPlan(p: AlertPlan): Promise<AlertStatus>; setRemind(change: PassRemindChange): Promise<AlertStatus>; status(): Promise<AlertStatus>; requestPermission(): Promise<boolean> };
  fileExport?:  { save(file: FileExport): Promise<'saved' | 'cancelled'> };
  diagnostics?: { snapshot(): Promise<DiagnosticsSnapshot>; export(): Promise<void> };
  keepAwake?(on: boolean): void;
}
```

Members marked `?` exist only on the `ios` host. Web code checks `capabilities`, never `kind`.

The iOS seam exposes `startup()` through `startup.v1`. Its local descriptor has two cases: `public` with the selected baseline version, and `account` with the selected verified account snapshot version. Read it from native state for the committed bundled document. Bind the descriptor, the snapshot read and the local artifact routes to the same document scope. Native starts a new document when switching between public and account scope.

### What each member does on each host

| Member | `browser` | `ios` |
| --- | --- | --- |
| `request` | `fetch(path, init)` with the same options as today | Routed by `routes.json`, below |
| `online` | `navigator.onLine` | The system network path is usable |
| `probe` | Today's `/__opd_probe` fetch | Native asks the Worker; true only on a real answer |
| `snapshot` | `localStorage`, scoped by account and profile generations and data revision under W-20 | `read` uses the selected serving snapshot before the first render. Select the public baseline until a complete verified snapshot is ready for the active account. `write` does nothing because native owns both snapshots. |
| `outbox` | Today's `opd-calib-queue` code, moved | Native outbox. `enqueue` resolves only after the entry is on disk. |
| `tileUrl` | Returns `upstream` unchanged | Returns the tile route for that layer |

### Request routes on the `ios` host

`frontend/src/host/routes.json` is the one table. Native code reads the same file from the app bundle. A test fails when the frontend requests a same-origin path the table does not classify, so a new web request cannot reach the app unrouted.

| Path | Class | How the `ios` host answers |
| --- | --- | --- |
| `/manifest.json`, `/v/<version>/*` | plan | From the same serving snapshot as `host.snapshot.read()`. While the public baseline serves, only its manifest and indexed artifact paths resolve. After account snapshot activation, only that account's installed plan and granted artifacts resolve. |
| `/launch/latest.json`, `/launch/v/*`, `/launch/catalog/*` | published | Verified stored pointers, bodies and [schedule evidence](#launch-schedule-evidence), refreshed independently of the account manifest. Apply the selected feed and validity rules in [Alerts](#alerts) before scheduling. |
| `/hazards/v1/*` | published | Network; last good copy, marked stale, when offline |
| `/lightning/latest.json` | live | Network only. It is stale after eight minutes by design. |
| `/api/browser/session` | identity | The serving account snapshot's validated answer from `/d/session`, refreshed by sync. The public baseline uses the local startup descriptor. The route is unavailable in a public document. |
| `/api/log` POST | outbox | Not called. `calib.ts` uses `host.outbox` when the capability exists. |
| `/api/log` GET, `/api/browser/profiles/*`, `/api/kp`, `/api/aurora` | api | Network with the device token, sent to `/d/api/...`. Offline, it rejects like a failed `fetch`, so today's error paths run. |
| `/api/wx`, `/api/cloud` | api | Network with the device token, sent to `/d/api/...` for verified public targets only. Public lookups use the same offline failure path. Apply [target request privacy](#target-request-privacy) before dispatch. A private target uses locally available conditions. |
| `/api/cal`, `/api/cal/handoff` | absent | The Remind flow uses `host.alerts` on iOS. Calendar file routes are website-only. |
| `/api/app`, `/sw.js`, `/registerSW.js` | absent | Not built into the app. The iOS build has no service worker. |
| `/__opd_probe` | probe | Same as `host.probe()` |
| `/glyphs/<fontstack>/<range>.pbf`, built frontend chunks and stylesheets, emitted ISS label catalogs | bundled | `GET` of exact paths in the build's asset index. Read only bundled bytes, with no credentials or network fallback. |

Build the asset index from the shipped files. Apply the [roster distribution rule](#personal-target-import-sources) to the indexed files and the rest of the frontend build. Include the emitted paths for `label-catalog.json` and `label-catalog-towns.json` under their actual build names. Both ISS catalog loads use `host.request` with the canonical path resolved from the emitted asset URL. The bundled host validates canonical paths against the index for both direct asset loads and `host.request`. Resolve the percent-encoded glyph fontstack to its exact indexed path. Unknown paths and traversal attempts fail closed.

Navigations are routed too. `/`, `/?u=<name>` and `/<name>` load the shell, because the profile menu switches profile with `location.assign` (`frontend/src/profile-menu.ts:89`). The sign-in recovery navigation to `/api/app` and the calendar navigation to `/api/cal` do not exist on the `ios` host. A link to another site opens in Safari.

Map import recovery uses those same bundled shell navigations. Allow `map-chunk=1` for the single automatic reload after a chunk 404 and `map-retry=<nonce>` for the Retry action. The markers may coexist after Retry follows that reload. Preserve the existing profile selector and apply normal shell and account authorization on each navigation. Each reload starts a new document generation.

The iOS seam checks the local origin of each chunk probe and module source URL, then sends its relative path and query through `host.request`. For `GET` of indexed emitted JavaScript chunks only, allow `map-probe=<nonce>` and `map-retry=<nonce>`, including a probe of a retry-qualified chunk. A nonce is 1 to 20 decimal digits. Reject repeated or unexpected query fields. These values vary the request's cache key only. Resolve disk reads by canonical indexed path and return the same bytes and media type as the unqualified asset. Retry reads the shell's static dependencies and the map's nonce-qualified dependency graph, applies the bundled MapLibre stylesheet, and evaluates fresh Blob modules created from the indexed source bytes in the bundled document. Keep the running shell's module identities and clear the recovery markers after Map renders. All of these reads stay local.

Give each row in `routes.json` a method allowlist, a parser for its path parameters and query fields, and a request header and body schema. Native code accepts messages only from its own web view, in the expected content world, from the bundled main frame at the local origin and an allowed shell document. Check WebKit's trusted frame, origin and document metadata. Block remote web view navigation and open external links outside the bridge. Start a new native document generation on each main-frame navigation. Accept messages only after the bundled shell commits and receives a new document nonce through the native bridge. Reject queued messages with the previous nonce. Use WebKit metadata and native state to establish document trust and account identity. [WebKit frame metadata](https://developer.apple.com/documentation/webkit/wkframeinfo)

Accept only relative canonical routes. Reject ambiguous or multiply decoded paths, foreign origins, unsupported methods, invalid query fields, and headers outside each route's allowlist. Decode route parameters once using their schemas and reconstruct the URL from the validated components. Native code supplies authorization, build information and content headers. Requests with account credentials use the configured Worker HTTPS origin and a separate session with no web view cookies. Reject all redirects on these requests, including same-origin redirects. Handle provider login callbacks in their dedicated native sign-in flow.

Attach the native document generation and active account activation to each account operation, including local reads, log enqueue and drain, profile mutations, alerts and network requests. Resolve the account and allowed profile from native state. Bind private reads, including reads of installed artifacts and cached profile data, to the profile generation and data revision authorized at admission. Check those bindings and [the current account authorization](#profiles-sign-out-and-deletion) before starting and again before returning a result, committing a local change or scheduling an alert. Invalidate pending operations on navigation, sign-out, account switch, revocation or an advance of their bound data revision. Apply private results only in their originating document and profile data revision. Treat enrollment, deletion status and revocation-only calls as dedicated native operations. They cannot expose a privileged request or credential to JavaScript.

The web side keeps polling `/manifest.json` every 60 seconds. On the `ios` host that read is local and returns the current serving snapshot's manifest. Native code also fires `plan-installed` after activating a complete account or baseline snapshot. The iOS path applies the local snapshot to both renderers and the queue on that event even if the network is unavailable.

### Files export on iOS

Profile JSON and Photo Lookup KML use their existing serializers. Serialize profile data from the current authorized revision. On iOS, the export buttons use `file-export.v1` to send a `FileExport` with the allowlisted kind (`profile-json` or `photo-lookup-kml`), suggested basename and bounded UTF-8 contents through the trusted main-frame bridge. Validate the basename and payload size and enforce the extension for each kind. The browser keeps its existing download path.

Present the system Files folder picker from the export action. Use the returned security-scoped directory for one coordinated write. Create the file exclusively so a name collision preserves the existing file. Resolve `saved` only after the destination write succeeds. Resolve `cancelled` if the picker is dismissed, and reject with a user-visible error if the destination is unavailable or the write fails. Remove any partial file created by the attempt. Keep export contents and destination paths out of logs and release the directory access when the operation ends. A local Files destination works offline. [Apple directory access](https://developer.apple.com/documentation/uikit/providing-access-to-directories)

Bind the export to the originating document and its scope. Bind a profile export to the authorized account activation, selected profile generation and validated data revision. Order the final write admission with document and scope invalidation and recheck the binding after the picker and before writing or replying. If invalidated before the write starts, dismiss the picker and discard the staged bytes. Send the result only to the still-current originating document. Completed files in Files are user-managed copies.

### Storage, in two tiers

- **Tier 1, durable native storage.** Installed plans, the profile binding, the device token, and the outbox. A write is acknowledged after it is on disk.
- **Tier 2, recoverable web storage.** The `ios` host mirrors `opd-` preferences, personal target copies, and caches to native storage for the active account. It restores only that account's mirror. Signed-out baseline state has its own namespace. The bundled curated targets and baseline map pack are shared.

Key installed plans, mirrored web storage, account-derived caches, and alert plans by the stable account ID. On sign-out or account change, detach the old account's plan and caches and clear their web-view copies. Start a new bundled shell document bootstrapped from the new account or baseline snapshot so both renderers drop their outgoing in-memory state. Bind in-flight sync, mirror, and alert work to the account activation that started it. Discard results from an earlier activation, including one that finishes after a switch back. When sync confirms a grant was removed, stop serving the affected profile and clear its installed and staged artifacts, cached views, and alerts. Apply the new grants before publishing sync results.

When a validated session advances a profile's data revision, durably close its earlier-revision reads and remove its superseded private state before publishing new results, even if the grant and manifest version stay the same. Retire the nonce and detach any document that could hold or apply results for the erased revision as cleanup begins. A reply already queued in WebKit belongs to the detached document. Bootstrap the replacement shell from authorized, verified data or the public baseline while refreshing. Resume interrupted cleanup before restoring the affected account data on relaunch. Clear notifications as described in [Alerts](#alerts).

### Tiles

`frontend/src/host/tile-layers.json` lists every tile layer once: an id, the upstream URL template, the attribution text, the deepest zoom and a storage policy. The web side builds map sources from it through `host.tileUrl`. Native code reads the same file. A tile URL template that is not in the catalogue fails a test.

| Policy | Meaning | Layers in release 1 |
| --- | --- | --- |
| `baseline` | Bundle separate raster MBTiles at zoom 0 to 5 and a GeoJSON lines and labels asset. Include attribution for each asset. | Blue Marble, Black Marble 2016, Natural Earth lines and labels |
| `durable` | Kept on disk after fetch, inside the tile-store cap | GIBS daily true colour (latest two days), SNAP forecast cloud frames |
| `session` | Kept briefly | Geostationary IR, RealEarth Meteosat |
| `online` | Fetch on demand where the source terms permit. Prefetch and disk retention are disabled by default. Enable offline use only under [confirmed permission for the exact sources and use](../designs/ios-app.md#esri-rights). | Esri imagery, Esri dark grey, Esri reference labels |

The gateway answers in this order: baseline pack, tile store, network. A miss with no network returns nothing and the map overzooms the baseline. The baseline sits under the online layers in the map style, so a missing Esri tile shows Earth, not black.

The baseline MapLibre sources and gateway use XYZ coordinates. The pack stores rows in TMS order. For each baseline database lookup, the gateway converts the XYZ row to `tile_row = 2^z - 1 - y` once, at the MBTiles boundary. Tile-store keys and upstream requests keep XYZ coordinates. [MapLibre raster scheme](https://maplibre.org/maplibre-style-spec/sources/#raster-scheme) · [MBTiles tile rows](https://github.com/mapbox/mbtiles-spec/blob/master/1.3/spec.md#tiles)

The iOS ISS view composer requests both raw NASA rasters through `host.tileUrl` and the gateway. If either exact tile above zoom 5 is unavailable, the composer requests both bundled zoom 5 parents for that XYZ coordinate. It crops each parent to the requested child's extent, resamples to the 256-pixel tile size, and lights the result for the child's coordinates and requested time. The pair always comes from the same zoom and footprint. Treat a fallback result as temporary so it cannot replace exact imagery once both exact tiles are available. The camera can still zoom in. W-42 checks the resulting pixels with empty caches and no network.

The tile store has a 512 MiB cap (536,870,912 bytes), measured as the sum of downloaded tile payload bytes across all layers. The bundled baseline pack, installed plans and outbox are outside this cap. Before storing a tile, remove expired tiles, then evict least-recently-used tiles until the new tile fits. Do not store a tile larger than the cap. Layer retention rules are upper limits within this cap. A fill-and-evict test checks the byte total, eviction order and preservation of the baseline, plans and outbox.

The iOS host disables Esri world-view and per-target prefetch by default. After each new plan, `frontend/src/tile-precache.ts` routes permitted GIBS prefetch through `host.tileUrl` to the gateway. Up to three eligible public targets get one tile per source zoom at 6, 8, and 9. Requested zoom 10 clamps to source zoom 9. The browser host keeps its world-view prefetch and applies the same public-target eligibility rule to each source's existing per-target prefetch. W-42 verifies offline baseline rendering and attribution with Esri disabled.

Release 1 disables external place search in the iOS build. Users add personal targets by coordinates or map pin and can name them locally. The iOS build omits the geocoder and its controls. Its outbound policy denies geocoder requests. Entered names and coordinates go to SNAP only as saved target data when authenticated sync runs. The privacy policy discloses that transfer.

### Browser place search

Both website hosts keep explicit place search. Use bounded, short-lived caching in memory for the active search document and account activation. Keep entered queries and returned place names and coordinates out of persistent browser caches, including HTTP cache for new searches. Cancel queued and in-flight searches on teardown or scope change. Check the current document, scope and search before caching or displaying a result even if the request completed after cancellation.

As part of W-21's [legacy context migration](#plan-artifact-authorization), retire the legacy pages on the origin, then have the replacement page delete `opd-geocode-cache-v1` from local storage and verify it is absent. ### Target request privacy

On iOS and both website hosts, only verified public targets may trigger a live weather request or target-derived tile request. Check the effective target against its authoritative public catalog entry and check its provenance before weather lookup, thumbnail or camera tile selection, and prefetch. A personal target, a private override of a public ID, or an unclassified row uses the private path even if its coordinates match a public location. Apply the rule to published and device-computed passes as well as map targets. A private target keeps local geometry and any authorized at-pass score from the plan. Omit live cloud and station weather for that target. Its thumbnail and target-driven viewport use bundled or independently cached public imagery where available and a local fallback where it is missing. Make no upstream request or new tile cache entry for its footprint. Ordinary viewport requests selected independently of a private target can still use permitted on-demand sources.

Send only the verified public target ID to `/api/cloud` and `/api/wx` or their `/d/api/` equivalents. The Worker resolves coordinates from the public catalog and rejects raw coordinate queries and unknown IDs before any provider fetch or cache access, including on legacy aliases and `HEAD`. Store new weather cache entries under public catalog IDs and revisions. Today's cloud proxy sends four-decimal coordinates to Open-Meteo, and today's station weather proxy sends target-centered METAR and TAF bounds to AviationWeather.gov and can persist `CALIB/wx/<lat>_<lon>.json`. Apply the private-target rule at the frontend before forming a weather query or an upstream GIBS or Esri tile URL. Saved personal targets still use authenticated SNAP reads and writes, and the [generator forecast transfer](#contributions-to-shared-profiles) has its separate 0.25° policy.

Before deletion enablement, close legacy weather admission and tile prefetch fills, settle in-flight writes, and retire all legacy coordinate-keyed weather caches. Purge operator-controlled copies, including `CALIB/wx/` keys, edge and upstream-fetch cache entries under SNAP's control, browser and native weather caches, and target-derived tile footprints in legacy local tile stores and Cache Storage. Include coordinate-bearing access logs, traces, backups, and support copies. Remove the affected namespace or file if private entries cannot be reliably separated. Apply the [browser and edge cutover](#plan-artifact-authorization) for cache expiry, verification, and legacy browser contexts. Prevent late fills and verify readback before enabling deletion. Any retained target-derived copy still under SNAP's control remains in scope for erasure. Exclude raw weather queries from ingress logs and keep request diagnostics free of private target names, coordinates, bounds, and tile footprints. Disclose prior provider transfers and retention limits in the privacy policy.

### Browser calendar selections

On each website host, bind Remind selections to the validated acting account generation, destination profile generation and profile data revision. Store the opaque calendar source reference and its contribution-version IDs. For published rows, obtain the reference with the [publisher's pass provenance](#contributions-to-shared-profiles), including for `cupola_windows`. Those fields are the target ID, name, closest-approach time and optional off-nadir angle and ISS-relative bearing. Keep the source resolvable by its opaque reference through closest approach even if ordinary pruning removes its artifact, and expire it when the pass is no longer future. Apply the same grant and revision checks as for the originating artifact. A selection can retain its reference across an offline reload and prepare a handoff when the browser reconnects. The Worker uses only its verified source projection, including for a previously verified computed pass, when the versioned row is gone. Keep these projections in the erasure inventory and index them by profile generation and contribution-version IDs. Invalidate affected references at deletion acceptance and verify erasure of their fields, bindings and related handoffs before cleanup completes. Ordinary plan pruning can remove the versioned artifacts on schedule.

Use the same per-origin cross-tab ordering as private snapshot writes. On sign-out or scope change, detach the old selection. On authoritative account or profile deletion or grant loss, remove the affected selection. On a validated revision advance with the same grant, block the old list and export as soon as the revision is recorded. Reconcile saved selections against authorized pass data and provenance for the new revision. Keep only future selections that can be matched unambiguously to the same surviving pass and contribution, including verified public passes. The Worker can carry a retained source into the clean revision only after checking its exact verified lineage against the erasure decision and current authorization. A reused target ID and time alone cannot establish a match. Build export fields from the clean revision and erase the superseded entries before exposing the reconciled list. Preserve other authorized scopes. Reject late toggles, reads and restores for a closed scope or superseded revision, including in a tab still waiting for its notice.

Prepare the handoff online before the Add to Calendar click. Use a same-origin `POST /api/cal/handoff` with the selected calendar source references and their contribution-version IDs in the body. The Worker verifies the current website session, acting account generation, destination profile generation, grant and profile data revision. Resolve each reference to a still-future authorized source for that revision and verify its provenance. Store only the authorized references and binding in private state under a random opaque ID with a two-minute absolute expiry. Recheck the binding and create the record under the same durable ordering as deletion and revision changes. Recheck the binding and source validity under the [final response gate](#plan-artifact-authorization) before releasing any response headers or calendar bytes. ## Native parts

`OPDKit` holds the logic and is pure Swift so it can be built and tested on the Mac today, which has Swift but no Xcode. Tests use Swift Testing. Every part takes its clock, file system root and transport as parameters.

| Part | Job | The property its tests must hold |
| --- | --- | --- |
| PlanStore | Stores installed plans under Application Support by account. Keeps the current plan, the previous one, and one more for each account. | Stop the process between any two steps of an install. `current` still resolves to a complete plan for the same account and every artifact matches its SHA-256. |
| SyncEngine | Downloads the account's filtered manifest and artifacts to a staging folder, verifies required fields and hashes, installs, and backs off on failure. Runs on foreground, on connectivity, on a timer, and in background refresh. | A failed or partial download leaves `current` intact. For the active account, the newer readable version wins. An unreadable version stays out of `current` and the app says an update is needed. |

### Sign in with Apple

```
App                                                     Worker
 │ POST /d/enroll/apple/session ──────────────────────► create a short-lived session with an unpredictable nonce
 │ ◄────────────── {session_id, nonce} ────────────────┘
 │ Set the nonce on the native Apple authorization request
 │ Receive the identity token and authorization code from Apple
 │ POST /d/enroll/apple {session_id, identity_token, authorization_code, attestation}
 │                                                         ► verify enrollment proofs, consume session, exchange code, save token response
 │ ◄────────────────── {token, profile} ─────────────────────┘
```

The Worker verifies the incoming identity token's signature against Apple's published keys, issuer (`https://appleid.apple.com`), audience (the app's bundle ID), and expiry. It requires the signed `nonce` claim to match the nonce stored for `session_id`. Only one request can atomically consume the unexpired session. The Worker then exchanges the single-use code at `POST https://appleid.apple.com/auth/token` with `grant_type=authorization_code`. Verify the returned identity token and require its Apple subject to match the nonce-verified token's subject.

Before sending a code to Apple, check the permanent-deletion fence and durably record the exchange as unresolved for the verified Apple subject, even before any SNAP generation exists. Record the enrollment attempt ID and its nonce issuance time. Serialize exchange admission, credential changes, enrollment commit, and deletion acceptance for that subject. Allow a verified deletion event to acquire the subject lock while an exchange is awaiting Apple. Check the fence again when the exchange returns and before committing the account, profile, and installation binding or issuing device access. On verified enrollment or re-enrollment, atomically store the encrypted token response for that authorization and resolve the exchange before issuing SNAP device access. Bind each installation to its verified Apple authorization. Keep an encrypted revocation credential and its revision for each Apple authorization that could still be live, including after an installation signs out. Enrollment cannot drop an earlier credential without provider evidence that its authorization has ended. An exchange that loses the race can supply verified credentials for provider settlement. It cannot create or update an account or issue access. [Apple's identity-token verification](https://developer.apple.com/documentation/signinwithapple/verifying-a-user)

Invalidate its activation, stop sync and alert scheduling, and clear its pending and delivered alerts. If it was active, return to the baseline and hide its plan and mirrors. Keep its unsent logs and deletion-check credential. Run the independent SNAP deletion check even after this sign-out and purge the outbox if SNAP confirms deletion. [Apple credential revocation](https://developer.apple.com/documentation/authenticationservices/asauthorizationappleidprovider/credentialrevokednotification)
- The owner's device list shows each account, its devices and their last build, and can revoke any of them.

### Apple deletion receipt

Before sending the deletion request, native code generates a high-entropy receipt and saves it separately from the account credential. It sends the receipt hash with the request. The Worker binds that hash to the deletion job when it accepts the request. `GET /d/account/delete/status` uses the receipt as a bearer credential and returns only deletion state and timing. The receipt grants no other access. Keep the status response uncached and the receipt out of JavaScript, URLs, logs, and diagnostics.

The app can check the receipt after clearing the account credential. Settings shows deletion status and the expected completion time, within 24 hours of acceptance. If more time is needed, keep showing pending and say that deletion is taking longer than expected. Recheck on relaunch or reconnect and show confirmation when the status is complete. The manual-revocation path reports that action is required. Keep status available while deletion is pending and for 30 days after it completes or reaches the manual-revocation state. A terminal status keeps no account identifier or provider token. Store the terminal status before removing the job state needed to recover after interruption. [Apple's account deletion guidance](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion)

If the initial response is lost, use the saved receipt to recover the result. A returned status confirms acceptance and triggers the same local cleanup as the initial response. If the Worker has no status for the receipt, the app shows that acceptance is unconfirmed and can retry with a valid account credential and fresh Apple proof if required. The same receipt and the same account can only identify one deletion job.

Test Apple deletion with the retained enrollment credential, a matching fresh code, wrong-account proof, an expired or consumed code, provider failures, and the manual-revocation path. Drop the initial response after acceptance, restart the app and Worker while pending, and delay revocation or artifact purge past the expected time. Verify that the app recovers the same receipt, clears local state, stays pending past the deadline, and confirms completion after revocation and cleanup succeed. A lost response before acceptance stays unconfirmed. An invalid receipt reveals no status and a valid receipt cannot read any other route.

### Before sign-in

A signed-out app starts from a bundled, schema-validated baseline snapshot. Build it from the public curated targets and a public CelesTrak ISS element set. Give it a baseline-only manifest version and exact indexed local artifact paths and hashes. Include a valid `Track` with the public element set and its actual epoch, the curated `targets`, and empty `passes`, `top5`, and `top_24h` arrays for the published slots. The snapshot has no publisher status or personal variants. `host.snapshot.read()` provides the matching manifest and track before the first render, including during LOS. The local manifest and versioned routes then supply Map's `passes` and `track` reads and other baseline artifact reads from that same version. ISS view receives the manifest version and track from the snapshot. Use SGP4 with the public element set for the moving ISS prediction beyond the sampled track window, and use the same element set and curated targets for W-12's device-computed passes.

In normal startup, read the iOS startup descriptor before the browser profile resolver or any personal-state initialization. The `public` branch has no account profile or grants and needs neither a session request nor a session cache entry. It ignores profile selectors in the URL, skips private menus, profile loading and subscriptions, private target hydration, and outbox access. Continue through the common snapshot hydration and public render path regardless of link state. Show Sign in or the native account's awaiting-sync state as appropriate. The `account` branch validates the selected snapshot's local account session and grants without using network reachability to decide whether to read the bridge. Website startup continues to validate the website session before loading private state.

When connected, fetch the public ISS element set directly from CelesTrak at most every few hours. Validate a newer element set and prepare a complete baseline manifest, artifact set, and snapshot with a matching track before atomically selecting them for the baseline scope. Keep the last complete baseline on a failed or interrupted update, and keep the bundle available on a clean install. Report the true orbit epoch and age. Baseline boot and refresh use the public snapshot in its own namespace at first launch, after sign-out and after enrollment until the first verified account snapshot is ready. Map, ISS view and Queue continue using the same baseline data across link loss and cold relaunch. Account plans, personal tile caches and private bridge routes stay inaccessible to the baseline document. Native sync can use a valid enrolled credential to stage and verify the first account snapshot. App Review's synthetic demo is a separate, explicit mode.

## What happens when

| Moment | What happens |
| --- | --- |
| First launch, no account | The bundled public snapshot starts Map and ISS view and supplies curated targets and orbit data for device-computed passes. A Sign in button offers Sign in with Apple and Google. |
| Link drops just after credential issuance | Keep the public snapshot, local artifact routes and baseline queue active while the first account snapshot awaits sync. Resume native sync when the link returns. |
| Cold launch, no signal | The shell loads from the app. The snapshot and local artifact routes use the active account's verified installed plan if available, or the public baseline. Map, ISS view and Queue use that same version and orbit epoch. The banner shows LOS and the relevant local data's age. |
| The link returns, app closed | If iOS grants a background refresh, sync installs a newer plan and the outbox drains. Alerts roll forward when scheduling inputs match, including a verified scores-only change or a catalog lease renewal that still validates the requests. Changed scheduling inputs pause affected alerts until the next open. If iOS defers refresh, sync and drain wait for the next open. |
| Shoot tapped with no signal | The entry is written to the outbox, then the screen confirms. It uploads once when the link returns. |
| The web process is killed | The web view delegate reloads the shell. The web side restores the tab and the aim from storage, as it does after a browser reload. |
| An install is interrupted | The staging folder is discarded at next launch. The previous plan stays current. |
| The token receives an ordinary `401` | Sync and the outbox pause. A banner offers sign-in. Reading the active account's installed plan continues. |
| Native sync learns the account was deleted | Local account cleanup runs before any further sync or alert work. The baseline replaces the deleted account's state. |
| The orbit data is old | The position readout shows the orbit age. Device passes and their alerts carry the same approximate marker when their closest-approach time minus the element epoch exceeds W-12's validated age, or on every device pass if no age passes validation. Installing newer orbital inputs clears superseded pending alerts and their coverage before the replacement plan can schedule. |
| Storage is nearly full | Tile storing stops first. Plans and the outbox are never trimmed. |
| A newer plan or a `/d/*` response is unreadable | Reject it before changing the installed plan, validated session and grants, or the outbox. Keep serving the last good state within the active account's last validated grants. Defer account sync and outbox drain until a readable reply allows recovery. Show an update message. A separately validated deletion or revocation signal still applies. |
| A new build is installed over the old one | The credential, installed plans, outbox, kept tiles and settings carry over. |
| A ground build nears expiry | Show a banner from 30 days out and an alert at 10 days. TestFlight uses its App Store Connect build deadline. Ad hoc uses the provisioning profile expiry. Ask the ground tester to install the replacement on the same channel. App Store installs have no expiry display or alert. Missing receipt data leaves launch available offline. |

## Rules the build enforces

These extend the rules in `AGENTS.md`. Each gets a test that fails with the file and the rule named.

- Nothing outside `frontend/src/host/` names the bridge, the host template or `webkit.messageHandlers`.
- No `fetch(` to a same-origin path outside `frontend/src/host/`.
- Every same-origin path the frontend requests is classified in `routes.json`.
- Every tile URL template is in `tile-layers.json`.
- Web code reads `host.capabilities`, never `host.kind`, outside the seam.
- `OPDKit` imports no UIKit and no WebKit, and its tests import `Testing`, not `XCTest`.
- No key, certificate, provisioning profile or token is in the repository. Workflows name secrets; they never print them.
- No iOS work package changes `generator/`.
